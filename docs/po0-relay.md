# PO0 独立中转脚本

`scripts/po0-relay.sh` 是单文件 Bash 脚本，适用于使用 systemd 和 nftables 的 PO0 IPv4 中转机。复制这一份文件即可使用，不需要 vpsctl、仓库公共库、代理内核或 jq。原脚本的 Ubuntu 22.04 / 24.04 是目标环境；实际测试平台见验收记录。

```bash
sudo bash po0-relay.sh
sudo bash po0-relay.sh --status
bash po0-relay.sh --help
```

无参数进入交互菜单；`--status` 只查看状态，`--help` 显示帮助。菜单需要终端，不接受通过管道直接输送回答。

## 管理线路

菜单提供查看、新增、编辑、启用或停用、删除、状态和重新应用配置。

新增时依次填写名称、入口端口、目标 IPv4 和目标端口，再按编号选择 TCP、UDP 或 TCP＋UDP。入口留空会建议一个经过冲突检查的随机端口，协议默认为 TCP＋UDP。提交前展示摘要并确认一次；输入错误可以在当前步骤重填。

每条线路直接保存目标，修改一条线路不会改变其他线路。入口支持单端口或 `START-END` 区间，区间内每个入口都映射到同一个目标端口。例如：

| 名称 | 协议 | PO0 入口 | 目标 |
| --- | --- | --- | --- |
| 香港 | TCP＋UDP | 20001 | 198.51.100.2:443 |
| 日本 | UDP | 20010-20020 | 198.51.100.3:8443 |

这些是文档示例地址，使用时替换为实际目标。入口指 PO0 网卡上的本机端口；若服务商另有公网到内网的端口映射，仍须使用现有映射对应的入口，脚本不会修改服务商配置。

编辑先选择线路，再选择字段，回车保留已有值；输入 `:q` 可取消当前操作，提交确认默认选择否。停用保留记录，删除移除记录。停用、编辑和删除作用于之后建立的连接；已有连接可继续到 conntrack 超时，脚本不清空系统连接跟踪表。

相同入口端口可以分别配置 TCP 和 UDP；相同协议的重叠端口、SSH 使用的 TCP 端口、相关本机监听占用，以及指向本机的目标会被拒绝。暂不支持域名、IPv6、端口区间逐端口偏移映射和一个入口多目标。

## 从旧脚本升级

保留旧 `/etc/nftables.conf`，直接运行新脚本。它识别原 PO0 脚本生成的完整模板，导入线路名称、入口、目标、网卡和 SNAT 内网地址，所有旧线路按已启用、TCP＋UDP 显示。

进入菜单或查看状态不会重写防火墙。第一次成功提交变更时才备份旧配置并保存新版 `/etc/po0-relay/state.tsv`。以后从该状态文件读取，重复运行不会重复添加旧线路。

识别不完整、配置损坏或存在无法确认归属的配置时，脚本会保留原文件并报错。自动接管只针对原脚本生成的配置；不要删除旧配置或状态文件来绕过提示，也不要同时用旧脚本覆盖新版配置。

## 系统行为

脚本保留旧版 `inet filter`、`ip nat` 和 `ip mangle` 三张表以及默认入站和转发丢弃策略，继续维护 SSH 和中转放行、SNAT、MSS 1452。更新以 nftables 原子批次替换受管表，不执行全局 `flush ruleset`。其他表保持原样；其他防火墙对同一流量的丢弃规则仍可能影响转发。

新版 DNAT 限定为从选定网卡进入、目的地址属于本机的流量。正常连接 PO0 本机入口的用法保持不变，不将它作为截获任意过境流量的路由器使用。

每次提交先验证候选配置，再应用并持久化。失败时恢复受管运行规则和配置文件；不会通过重启 nftables 服务来应用变更，因为该服务的停止动作通常会清空全局规则。成功配置由 nftables 服务在开机时加载，无需后台转发进程。

首次新装才选择网卡、内网地址并初始化必要设置；已有部署不因增删线路反复重设 BBR 等系统参数。缺少依赖时按实际操作提示安装，查看菜单不会自动安装软件。

## 恢复上一份配置

每次应用将恢复材料写入 `/etc/po0-relay/backups/时间戳.随机后缀/`，成功或失败时都会显示本次备份目录。目录中的 `before.txt` 记录原转发参数、服务启用状态和配置来源；`state.before`、`nftables.before`、`sysctl.before` 是原文件，某项不存在表示变更前没有这个文件。`runtime-restore.nft` 只包含三张受管表的恢复批次。

需要撤销某次变更时，在有 root 权限的终端中执行该次备份的恢复脚本：

```bash
sudo bash /etc/po0-relay/backups/实际备份目录/recover.sh
```

它会恢复该次变更之前的受管运行规则、配置文件、IPv4 转发开关和 nftables 开机启用状态，不重启服务、不清空其他 nftables 表。选择较早备份会撤销其后的线路变更。恢复到旧版时，新版状态文件也会移除，下次运行会重新识别旧模板。

首次部署只自动启用必要的 IPv4 转发并保存 `/etc/sysctl.d/99-po0-relay.conf`；旧 `/etc/sysctl.d/99-relay.conf` 中的 BBR、队列和 conntrack 参数保持不变，新装不额外强制这些调优值。

## 验证

定向测试和真实转发检查都必须通过 `ssh host-vps-scripts` 在专用环境运行。测试覆盖旧版导入、线路管理、冲突、TCP／UDP 和端口区间、SNAT 回程、失败恢复、其他表保留及持久化配置重新加载。实际执行范围与结果见 [PO0 验收记录](po0-relay-validation.md)。
