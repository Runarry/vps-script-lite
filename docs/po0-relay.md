# PO0 独立中转脚本

`scripts/po0-relay.sh` 是单文件 Bash 脚本，适用于使用 systemd 和 nftables 的 PO0 IPv4 中转机。复制这一份文件即可使用，不需要 vpsctl、仓库公共库、代理内核或 jq。URI 功能按需使用 Python 3 标准库，无需额外 Python 包；普通 IPv4 转发不依赖 Python。原脚本的 Ubuntu 22.04 / 24.04 是目标环境；实际测试平台见验收记录。

```bash
sudo bash po0-relay.sh
sudo bash po0-relay.sh --status
bash po0-relay.sh --help
```

无参数进入交互菜单；`--status` 只查看状态，`--help` 显示帮助。菜单需要终端，不接受通过管道直接输送回答。

## 管理线路

主菜单每项独占一行，顶部显示线路总数、启用／停用数、公网 IPv4、网卡及 SNAT 地址，操作分为：

- 线路管理：1 查看线路与 URI、2 新增、3 编辑、4 启用／停用、5 删除。
- 状态与维护：6 运行状态、7 刷新目标并重新应用。
- 全局设置：8 开启 BBR＋FQ、9 公网 IP 设置；0 退出。

新增时先输入节点 URI 或目标 IPv4；手填 IPv4 时再填写目标端口。随后填写名称、入口端口，再按编号选择 TCP、UDP 或 TCP＋UDP。URI 备注作为默认名称，无备注时使用“线路 ID”；入口留空会建议一个经过冲突检查的随机端口。协议默认为 TCP＋UDP，HY2／TUIC 默认 UDP，可以手动调整。提交前展示摘要并确认一次；输入错误可以在当前步骤重填。

每条线路直接保存目标，修改一条线路不会改变其他线路。入口支持单端口或 `START-END` 区间，区间内每个入口都映射到同一个目标端口。例如：

| 名称 | 协议 | PO0 入口 | 目标 |
| --- | --- | --- | --- |
| 香港 | TCP＋UDP | 20001 | 198.51.100.2:443 |
| 日本 | UDP | 20010-20020 | 198.51.100.3:8443 |

这些是文档示例地址，使用时替换为实际目标。入口指 PO0 网卡上的本机端口；若服务商另有公网到内网的端口映射，仍须使用现有映射对应的入口，脚本不会修改服务商配置。

编辑先选择线路，再选择字段，回车保留已有值；输入 `:q` 可取消当前操作，提交确认默认选择否。停用保留记录，删除移除记录。停用、编辑和删除作用于之后建立的连接；已有连接可继续到 conntrack 超时，脚本不清空系统连接跟踪表。

相同入口端口可以分别配置 TCP 和 UDP；相同协议的重叠端口、SSH 使用的 TCP 端口、相关本机监听占用，以及指向本机的目标会被拒绝。URI 内的域名会解析为 IPv4；手填目标继续只接受 IPv4。暂不支持 IPv6、端口区间逐端口偏移映射和一个入口多目标。

列表按线路分块展示，不依靠中文列宽对齐；中转 URI 完整占一行，方便复制。选择待编辑、启停或删除的线路时只显示简洁摘要。颜色只用于支持颜色的终端标题和提示，非终端、`TERM=dumb` 或设置 `NO_COLOR` 时为纯文本；不自动清屏。

## 使用节点 URI

支持 `vless://`、`vmess://`（Base64 JSON）、`trojan://`、`ss://`（SIP002 和旧版整体 Base64）、`hysteria2://`／`hy2://`、`tuic://`、`anytls://`。保留凭据、备注、传输、TLS 和其他参数，仅在必要时补齐原连接隐含的 SNI／HTTP Host。未知查询参数原样保留，不要求本机安装相应代理内核。

首次新增 URI 时使用 `https://api.ipify.org` 探测出网 IPv4，最多等待 5 秒，再提示填写实际公网入口。可以回车接受或手动更正；探测失败时直接手填。公网 IPv4 与线路一起成功提交后才保存。菜单 9 可手填或重新探测，适用于已初始化配置。SNAT 地址仍是本机网卡地址，两者分别保存。

例如上游为 `vless://凭据@198.51.100.2:443?security=tls&sni=origin.example#香港`，公网 IPv4 为 `203.0.113.9`、入站端口为 `20001` 时，查看和新增成功后输出的链接连接 `203.0.113.9:20001`，原凭据与 `sni=origin.example` 保留。以上均为示例值。服务商公网映射端口必须与填写的入站端口一致；脚本不修改服务商映射。

入站是端口区间时，分享链接使用起始端口并明确标注。HY2 原生多端口和 `mport` 会选定端口集合中的第一个端口作为固定目标；省略端口时使用 443。分享链接移除原 `mport`，不会让客户端跳到 PO0 未配置的端口。两处不一致的跳跃端口集合会拒绝。

URI 域名在新增、替换或菜单 7 刷新时解析为 IPv4，已有目标仍在解析结果中时继续使用，否则使用首个合法 IPv4。任一目标解析失败会中止本次提交，保留原配置；没有后台定时刷新。查看和 `--status` 不查询 DNS、不探测公网地址、不安装依赖。Python 缺失时仍能查看基本线路信息，会提示暂不能生成 URI。

编辑中的 **6）补录／替换节点 URI** 可为旧线路关联 URI，替换时同时更新目标；回车保留 URI。编辑目标 IPv4 或目标端口会同步修改 URI 模板，并保留原 TLS 名称和 HTTP Host；手动改成 IPv4 后，该线路不再跟随原目标域名刷新。修改名称不改写原 URI 备注。未关联 URI 的纯转发线路无法凭空生成节点凭据。

## 从旧脚本升级

保留旧 `/etc/nftables.conf`，直接运行新脚本。它识别原 PO0 脚本生成的完整模板，导入线路名称、入口、目标、网卡和 SNAT 内网地址，所有旧线路按已启用、TCP＋UDP 显示。

进入菜单或查看状态不会重写防火墙。第一次成功提交变更时才备份旧配置并保存新版 `/etc/po0-relay/state.tsv`。以后从该状态文件读取，重复运行不会重复添加旧线路。

状态 v2 保留原线路记录，并增加可选公网 IPv4 元数据和按线路 ID 关联的 URI 记录；兼容读取原 v1 状态，成功修改时才升级。URI 包含节点凭据，状态文件沿用 `0600` 权限，和线路一起备份、回滚，不写入 nft 配置。回退到旧脚本时，先使用对应备份恢复原状态。

识别不完整、配置损坏或存在无法确认归属的配置时，脚本会保留原文件并报错。自动接管只针对原脚本生成的配置；不要删除旧配置或状态文件来绕过提示，也不要同时用旧脚本覆盖新版配置。

## 系统行为

脚本保留旧版 `inet filter`、`ip nat` 和 `ip mangle` 三张表以及默认入站和转发丢弃策略，继续维护 SSH 和中转放行、SNAT、MSS 1452。更新以 nftables 原子批次替换受管表，不执行全局 `flush ruleset`。其他表保持原样；其他防火墙对同一流量的丢弃规则仍可能影响转发。

新版 DNAT 限定为从选定网卡进入、目的地址属于本机的流量。正常连接 PO0 本机入口的用法保持不变，不将它作为截获任意过境流量的路由器使用。

每次提交先验证候选配置，再应用并持久化。失败时恢复受管运行规则和配置文件；不会通过重启 nftables 服务来应用变更，因为该服务的停止动作通常会清空全局规则。成功配置由 nftables 服务在开机时加载，无需后台转发进程。

首次新装才选择网卡、内网地址并初始化必要设置；已有部署不因增删线路反复重设 BBR 等系统参数。缺少依赖时按实际操作提示安装，查看菜单不会自动安装软件。

## 恢复上一份配置

每次应用线路配置将恢复材料写入 `/etc/po0-relay/backups/时间戳.随机后缀/`，成功或失败时都会显示本次备份目录。目录中的 `before.txt` 记录原转发参数、服务启用状态和配置来源；`state.before`、`nftables.before`、`sysctl.before` 是原文件，某项不存在表示变更前没有这个文件。`runtime-restore.nft` 只包含三张受管表的恢复批次。

需要撤销某次变更时，在有 root 权限的终端中执行该次备份的恢复脚本：

```bash
sudo bash /etc/po0-relay/backups/实际备份目录/recover.sh
```

它会恢复该次变更之前的受管运行规则、配置文件、IPv4 转发开关和 nftables 开机启用状态，不重启服务、不清空其他 nftables 表。选择较早备份会撤销其后的线路变更。恢复到旧版时，新版状态文件也会移除，下次运行会重新识别旧模板。

首次部署只自动启用必要的 IPv4 转发并保存 `/etc/sysctl.d/99-po0-relay.conf`；旧 `/etc/sysctl.d/99-relay.conf` 中的 BBR、队列和 conntrack 参数保持不变，新装不额外强制这些调优值。

## 开启 BBR＋FQ

运行脚本后选择 **8）开启 BBR＋FQ**，确认一次即可设置当前 TCP 拥塞控制为 `bbr`、默认队列为 `fq`。通过 **6）状态** 或 `--status` 查看当前值。功能也可在尚未创建中转线路时使用，不会修改线路、nftables 或 IPv4 转发开关。

开机配置分别保存在 `/etc/sysctl.d/99-po0-relay-bbr.conf` 和 `/etc/modules-load.d/99-po0-relay-bbr.conf`。需要时加载当前内核的 `tcp_bbr`、`sch_fq` 模块；内核不支持或参数／文件写入失败会报错并恢复原参数、原文件。已经开启且配置完整时，重复选择不会再次写入。旧脚本的调优文件保持原样。

BBR 设置影响本机新建的 TCP 连接；纯 nftables 端口转发不在 PO0 终止 TCP，因此不能据此承诺转发提速。FQ 在这里设置为默认队列，现有网卡的队列不会被立即替换。内核参数的定义见 [TCP 拥塞控制说明](https://docs.kernel.org/networking/ip-sysctl.html) 和 [默认队列说明](https://docs.kernel.org/admin-guide/sysctl/net.html#default-qdisc)。

本操作的原参数与文件备份单独放在 `/etc/po0-relay/backups/bbr-时间戳.随机后缀/`：`before.txt` 为原值，`sysctl.before`、`modules.before` 为原文件（若原来存在）。该目录不包含线路恢复脚本，线路的 `recover.sh` 也不会撤销单独开启的 BBR＋FQ。

## 验证

定向测试和真实转发检查都必须通过 `ssh host-vps-scripts` 在专用环境运行。测试覆盖旧版导入、线路管理、冲突、TCP／UDP 和端口区间、SNAT 回程、失败恢复、其他表保留及持久化配置重新加载。实际执行范围与结果见 [PO0 验收记录](po0-relay-validation.md)。
