# 主管理脚本与 UI 设计

## 1. 入口与运行模式

主管理入口为 `bin/vpsctl`，支持两种等价的使用方式：

- 交互模式：终端中不带参数运行，进入两层菜单。
- 命令模式：使用 `vpsctl <domain> <action> [options]` 直接分发已登记功能。

内置的管理命令为：

| 命令 | 用途 |
| --- | --- |
| `vpsctl` | 有终端时进入菜单；无终端时输出一次环境面板 |
| `vpsctl menu` | 显式进入交互菜单 |
| `vpsctl env` | 重新检测并显示完整环境信息 |
| `vpsctl list` | 列出已登记的功能命令 |
| `vpsctl help` | 显示参数和调用说明 |

帮助和版本查询不会触发环境检测。交互菜单不允许在 `--non-interactive` 或没有终端时运行，避免自动化任务意外等待输入。

## 2. 启动检测

环境检测位于 `lib/environment.sh`，只执行本地只读操作，不访问公网、不运行 `sudo`、不修改系统。每次启动交互 UI 时检测一次，也可从菜单刷新。

UI 显示以下摘要：

- 主机名、兼容状态和当前用户权限。
- 发行版、版本、内核和 CPU 架构。
- 虚拟化或容器类型。
- CPU 核心数、型号、内存和根分区空间。
- 本机全局 IPv4/IPv6 地址；不发起公网 IP 请求。
- BBR 启用状态、内核可识别的 BBR 版本和当前 TCP 拥塞控制算法。

初始化系统、服务管理器、包管理器和会话信息仍会在后台采集，用于后续功能的能力判断，但不在 UI 中展示。BBR 是否启用以当前 `tcp_congestion_control` 是否为 BBR 系列算法为准；对于同样注册为 `bbr` 且未暴露模块版本的内核实现，UI 不猜测它属于 BBRv1、v2 或 v3，而是显示版本未暴露。

检测结果同时转换为能力标识，例如 `linux`、`pkg:any`、`pkg:apt-get`、`init:systemd`、`service:any`、`root`、`ipv4`。注册命令可以声明能力要求，菜单会据此标记可用性，直接分发也会在运行前拦截不兼容命令。

容器、WSL、未知发行版或缺少基础管理器时显示 `LIMITED`；非 Linux 显示 `UNSUPPORTED`。该状态只是入口层的快速提示，功能脚本仍必须自行验证它实际需要的全部前置条件。

## 3. UI 层级

```text
环境摘要 + 兼容状态
└── 主菜单（领域）
    ├── 系统维护
    ├── 服务管理
    ├── 应用部署
    ├── 网络管理
    ├── 安全加固
    ├── 备份恢复
    └── 监控诊断
        └── 已登记命令（摘要、风险、权限和可用状态）
            └── 命令详情与执行
```

UI 使用 ASCII 边框和少量可选 ANSI 颜色，适合普通 SSH 终端。颜色只在输出连接终端且未设置 `NO_COLOR` 时启用。`--no-color` 可显式关闭颜色，`--no-clear` 可保留菜单切换时的终端历史。

从菜单执行功能后，控制台会显示该功能的退出码并允许继续操作。退出控制台时返回最后一次已执行功能的退出码；如果本次会话没有执行功能则返回 `0`。直接命令模式始终原样返回功能脚本的退出码。

## 4. 扩展方式

领域和命令均由 `lib/registry.sh` 中的固定登记信息生成，入口不扫描目录，也不执行未知文件来发现功能。

新增功能时：

1. 在 `commands/<domain>/<action>.sh` 实现并测试独立脚本。
2. 在 `vps_registry_init` 中调用 `vps_registry_register_command`，登记标签、摘要、固定路径、风险、权限、演练支持、能力要求和生命周期。
3. 更新 `docs/command-registry.md` 的公开命令清单和详细说明。
4. 运行 `bash tests/run.sh`。

菜单和 `vpsctl list` 会自动使用登记数据，无需修改 UI 代码。登记路径只接受与登记动作同名的 `commands/<domain>/<action>.sh`，分发时还会拒绝符号链接，从结构上阻止用户输入或被替换的链接指向任意执行路径。

## 5. 当前边界

首版主管理脚本已经提供环境检测、UI、注册表和安全分发框架，但尚未登记任何实际 VPS 功能。主菜单会显示规划领域及各领域的功能数量，进入空领域时明确提示尚无功能。
