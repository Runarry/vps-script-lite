# 主管理脚本与 UI 设计

## 1. 入口与运行模式

主管理入口为 `bin/vpsctl`，支持两种等价的使用方式：

- 交互模式：终端中不带参数运行，从主菜单直接进入所选功能自己的 UI。
- 命令模式：使用 `vpsctl <domain> <action> [options]` 直接分发已登记功能。

内置的管理命令为：

| 命令 | 用途 |
| --- | --- |
| `vpsctl` | 有终端时进入菜单；无终端时输出一次环境面板 |
| `vpsctl menu` | 显式进入交互菜单 |
| `vpsctl env` | 重新检测并显示完整环境信息 |
| `vpsctl list` | 列出已登记的功能命令 |
| `vpsctl help` | 显示参数和调用说明 |

帮助和版本查询不会触发环境检测。`list` 会执行一次只读环境检测，并在每个登记项旁显示“可用”或“受限”。交互菜单不允许在 `--non-interactive` 或没有终端时运行，避免自动化任务意外等待输入。

## 2. 启动检测

环境检测位于 `lib/environment.sh`，只执行本地只读操作，不访问公网、不运行 `sudo`、不修改系统。交互 UI 启动时检测一次；每个功能脚本返回菜单后再检测一次，使 BBR 等运行态变化立即反映在面板中。

UI 显示以下摘要：

- 主机名、兼容状态和当前用户权限。
- 发行版、版本、内核和 CPU 架构。
- 虚拟化或容器类型。
- CPU 核心数、型号、内存和根分区空间。
- 本机全局 IPv4/IPv6 地址；不发起公网 IP 请求。
- BBR 启用状态、内核可识别的 BBR 版本和当前 TCP 拥塞控制算法。

初始化系统、服务管理器、包管理器和会话信息仍会在后台采集，用于后续功能的能力判断，但不在 UI 中展示。BBR 是否启用以当前 `tcp_congestion_control` 是否为 BBR 系列算法为准；对于同样注册为 `bbr` 且未暴露模块版本的内核实现，UI 不猜测它属于 BBRv1、v2 或 v3，而是显示版本未暴露。

检测结果同时转换为能力标识，例如 `linux`、`pkg:any`、`pkg:apt-get`、`init:systemd`、`service:any`、`root`、`ipv4`。注册命令可以声明能力要求，菜单和 `list` 会据此标记可用性，直接分发也会在运行前拦截不兼容命令。入口只对精确匹配的静态只读调用移除其不需要的运行时能力：RFW 的帮助和无参数状态不要求 systemd，代理的帮助、协议矩阵、无参数状态与系统时间状态不要求服务管理器；Linux 等其余要求仍保留。多余参数以及任何变更动作（包括 `--dry-run`）都不能使用这些例外。

容器、WSL、未知发行版或缺少基础管理器时显示黄色“受限”；非 Linux 显示红色“不支持”；满足基础条件时显示绿色“支持”。该状态只是入口层的快速提示，功能脚本仍必须自行验证它实际需要的全部前置条件。

## 3. UI 层级

```text
环境摘要 + 兼容状态
└── 主菜单
    ├── 网络设置（network）
    │   ├── BBR 管理（bbr）
    │   ├── DNS 管理（dns）
    │   └── RFW 管理（rfw）
    └── 服务管理（service）
        └── 代理管理（proxy）
            ├── 内核生命周期：安装 / 更新 / 卸载
            ├── 服务控制：启动 / 停止 / 重启
            ├── 节点管理：添加 / 查看 / 修改 / 删除
            ├── 中转管理：出口 / 节点中转 / 纯端口转发 / 状态刷新
            ├── 查看与输出：订阅 / 日志 / 支持协议
            └── 系统工具：系统时间状态 / 同步
```

主菜单不会扫描目录或推测功能分类，只显示固定注册表中已经登记的真实功能。0.3.0 登记 `network` 与 `service` 两个领域，以及 `bbr`、`dns`、`rfw`、`proxy` 四个入口。用户选择功能后，入口立即无附加参数分发该公开脚本，由功能脚本进入自己的交互 UI；不再显示命令详情页，也不再要求输入 `r` 才运行。环境详情仍可通过非菜单命令 `vpsctl env` 查看。

`service proxy` 是一个公开登记入口，进入后使用自己的三级操作菜单。Xray 与 sing-box 在该菜单中平级展示并按需安装；每次进入或返回菜单都显示两个内核的状态、配置路径、各自节点数和总节点数，随后按能力分组提供操作，而不是先绑定某个内核。生命周期和服务操作会按当前安装/运行状态过滤候选；安装和更新在有多个候选时允许选择全部，其他动作解析到单个适用内核。其 `commands/service/proxy/` 私有模块不会作为额外菜单项出现。

所有功能 UI 采用同一输入约定：候选项、布尔开关、模式和其他封闭枚举必须展示为编号选项；地址、端口、名称、国家代码、日志行数等开放值可以文本输入，但必须在继续前完成与直接命令相同的格式和范围校验。菜单不要求输入 `--core`、节点 ID 或内部枚举字符串，也不把任意文本拼成命令参数。

代理菜单中的添加节点提供快速和自定义向导；profile 没有已安装的兼容内核时可引导先安装再继续。节点查看、编辑和删除先展示带所属内核标记的全量列表，再按编号选择。中转菜单中的出口、入口节点、关联和端口转发对象同样只通过编号选择；SS2022 普通/Padding 及多内核协议会显示明确的 profile/内核选择。订阅范围按编号选择“全部”，或选择当前确有普通节点或转发 URI 的 sing-box/Xray；没有内容的内核不会作为范围候选。`--core` 和 `--id` 仍保留给直接命令与非交互自动化，用于多候选场景的精确消歧。

RFW UI 的配置向导将 Geo 模式、各规则开关、FET、XDP 模式、端口访问日志和日志级别等固定值改为编号选择。启动可选“仅启动”或“启动并启用”，停止可选“仅停止”或“停止并禁用”；统计可选全部、仅拦截或仅允许，并可填写端口、IPv4 及是否按端口分组；日志可填写行数、是否跟随和可选的 `since`；卸载可选保留配置状态或彻底清除。彻底清除和中断性应用仍执行原有强确认。

注册表中的风险等级、权限、演练支持、能力要求和生命周期继续用于 `list`、能力门控和其他非菜单展示；主菜单不再插入命令详情页。展示层翻译注册值时，底层值和命令接口保持不变：`change` 显示为黄色“变更”，`disruptive` 显示为红色“中断性”，`optional-root` 显示为黄色“按需 root”，`supported` 演练显示为绿色“支持”，`experimental` 显示为黄色“实验性”。满足能力要求的命令标为绿色“可用”，否则标为黄色“受限”。能力标识只是入口层的快速拦截，功能脚本仍会再次验证内核、DNS 后端、CPU 架构、IPv4 等具体条件。

UI 使用 ASCII 边框和可选 ANSI 语义色，适合普通 SSH 终端：青色表示一般信息，品红加粗表示重点值，绿色表示成功或可用，黄色表示警告、受限或待应用，红色表示错误或中断性风险。颜色只在输出连接终端、未设置 `NO_COLOR` 且未指定 `--no-color` 时启用；以上任一禁用条件或非 TTY 输出都保证零 ANSI。`--no-clear` 可额外保留菜单切换时的终端历史。状态与安全语义不只依赖颜色，始终同时显示中文文字。

菜单只负责选择并真实执行功能动作，不提供 `--dry-run`、`--install-deps`、`--yes`、`--non-interactive`、`--quiet` 或 `--verbose` 等执行型全局参数开关；这些参数只允许随直接功能 CLI 使用。机器可读输出选项、`--force` 以及 `--confirm-*` 确认标志也属于 CLI-only 接口，不在菜单中暴露。菜单遇到危险动作时使用对应的交互确认或强确认短语，不能借由全局自动同意绕过。`--no-color`、`NO_COLOR` 和 `--no-clear` 仍只控制界面表现，不改变动作语义。

依赖也不在进入菜单时一次性预装。功能脚本只有在当前选定动作实际缺少可安装工具时才向交互用户说明缺失项并询问是否安装；拒绝安装只取消或终止该动作，不影响返回菜单。非交互调用不得询问，仍须由调用者显式传入 `--install-deps`。从菜单执行功能后，控制台会显示该功能的退出码并允许继续操作。退出控制台时返回最后一次已执行功能的退出码；如果本次会话没有执行功能则返回 `0`。直接命令模式始终原样返回功能脚本的退出码。

## 4. 扩展方式

领域和命令均由 `lib/registry.sh` 中的固定登记信息生成，入口不扫描目录，也不执行未知文件来发现功能。

新增功能时：

1. 在 `commands/<domain>/<action>.sh` 实现并测试公开入口脚本；复杂入口可按架构规范拆分同名私有子模块。
2. 在 `vps_registry_init` 中调用 `vps_registry_register_command`，登记标签、摘要、固定路径、风险、权限、演练支持、能力要求和生命周期。
3. 更新 `docs/command-registry.md` 的公开命令清单和详细说明。
4. 运行 `bash tests/run.sh`。

菜单和 `vpsctl list` 会自动使用登记数据，无需修改 UI 代码；`list` 还会根据当前环境标注每项“可用”或“受限”。登记路径只接受与登记动作同名的 `commands/<domain>/<action>.sh`，分发时会逐段拒绝符号链接，并由 Bash 读取固定登记的脚本，从结构上阻止用户输入或被替换的链接指向任意执行路径。

## 5. 当前边界

0.3.0 的管理入口已登记网络功能与代理管理。UI 只负责展示元数据、收集用户选择并分发，不实现 BBR、DNS、RFW 或代理业务逻辑。

网络功能的当前边界为：

- BBR 只管理拥塞控制、队列规则及其持久化配置，不负责升级或替换内核。
- DNS 只修改检测到的权威 DNS 后端；候选解析器必须先通过前测，写后验证失败会保留新配置并返回部分完成状态，以便按备份恢复。
- RFW 只支持 systemd、`x86_64`/`aarch64` 和 IPv4；安装只使用官方最新稳定 release 并校验 checksum。配置和更新不会自行重启服务，实际应用危险规则必须显式强确认。
- 代理管理支持 systemd 与 OpenRC，平级管理 Xray 和 sing-box，并提供出口驱动的节点中转和独立 nftables 端口转发；核心配置与内核更新不会自行重启正在运行的服务，端口转发则立即原子生效。卸载默认保留配置与中转状态，彻底清除、级联删除、外部二进制原地更新和中断性重启均有独立确认。

详细子动作、路径、恢复和验收要求见 [`docs/network-settings.md`](network-settings.md)与 [`docs/proxy-management.md`](proxy-management.md)。
